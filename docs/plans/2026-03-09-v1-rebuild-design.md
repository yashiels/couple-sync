# Couple Schedule v1 — Rebuild Design

**Date:** 2026-03-09
**Status:** Approved
**Branch:** feat/couple-schedule-mvp (will be rebuilt from scratch)

## Core Concept

Two people pair up, define their busy time (via Google Calendar sync + manual recurring/one-off blocks), and a server-side engine computes when they're both free. Results are ranked by quality and pushed to both partners.

## Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Platform | Mobile only (iOS + Android) | Ship to app stores, no web |
| Calendar sources | Google Calendar only (v1) | Simplicity, most users have it |
| Overlap computation | Server-side (Cloud Functions) | Scaling, data mining, consistency |
| AI suggestions | Cut for v1 | Nail core first |
| Pairing | Code + deep link | Code as fallback, link as primary |
| Recurring blocks | Essential + onboarding wizard | Most schedules are recurring |
| Unpair flow | Soft delete, re-pairable | Preserve data for mining, allow restore |
| Notifications | New free time alerts only (v1) | Keep it focused |

## User Journey

```
Sign Up (Google/Apple Auth)
    → Set Timezone (auto-detect + manual override)
    → Routine Setup Wizard (sleep, work, commute, etc.)
    → Pair with Partner (share link or code)
    → Home: See overlap results
    → Ongoing: Sync calendar, tweak blocks, view free windows
```

## Screens

### 1. Auth Screen

- Google Sign-In button
- Apple Sign-In button
- Creates/fetches user doc on success
- No anonymous auth, no email/password

### 2. Timezone Setup

- Auto-detect device timezone as default
- Searchable IANA timezone list to override
- Saves to user doc
- One-time during onboarding, editable in settings

### 3. Routine Setup Wizard

Step-through flow asking "When do you typically...":

- **Sleep**: bedtime + wake time (e.g., 11pm-7am)
- **Work/Study**: start + end, select days (e.g., Mon-Fri 9am-5pm)
- **Commute**: duration + days (e.g., Mon-Fri 7-8am, 5:30-6:30pm)
- **Skip** option for each step

Each step creates recurring TimeBlocks with appropriate category and RRULE. All times in user's local timezone, stored as UTC. Can be re-run from settings.

### 4. Pairing Screen

- **Tab 1 — Share**: Generate code, copy button, share deep link via any messaging app
- **Tab 2 — Enter Code**: Text field, validate, redeem
- Listens to user doc — auto-navigates to home when paired
- Re-pairing: if previously paired together, reactivate couple doc (restore data)

### 5. Home Screen

- **Timezone clocks**: Your time + partner's time, live
- **Next free window card**: Top-scored overlap with countdown
- **Upcoming windows list**: Next 5 windows in your timezone (partner's tz in parentheses)
- **Quick actions**: Add block, Sync calendar, View all windows
- Pull-to-refresh: sync + recompute

### 6. Calendar/Week View

- 7-day scrollable view, pageable by week
- Color-coded: your blocks, partner's blocks, overlap highlights
- Tap block for details (title, category, source, recurrence, owner)
- Tap overlap to see score/ranking
- Button to add new block

### 7. Overlap/Free Windows Screen

- All computed overlap windows (up to 20)
- Filter by minimum duration (any, 30m, 1h, 2h)
- Each card: date, time range (your tz), duration, partner's local time
- Sort by: score (default), date, duration

### 8. Block Management Screen

- List all your blocks (manual + synced)
- Filter by source (google/manual), category
- Edit/delete manual blocks
- Synced blocks read-only (delete to re-sync)

### 9. Block Form Screen

- Title, type (busy/free/tentative), category
- Date + time pickers (local timezone)
- Recurrence: none, daily, weekly (pick days), monthly
- Visibility: both partners / only me
- Validation: title required, end after start

### 10. Settings Screen

- **Calendar**: Connect/disconnect Google, last sync, manual sync
- **Timezone**: View/change
- **Routine**: Re-run setup wizard
- **Notifications**: Toggle new-window alerts
- **Couple**: Partner info, unpair (with confirmation)
- **Account**: Sign out

## Cloud Functions

### 1. onBlockWrite

- **Trigger**: Firestore onCreate/onUpdate/onDelete on `timeblocks/{coupleId}/blocks/{blockId}`
- Fetch couple doc → both user timezones
- Query all blocks for couple (14-day horizon)
- Expand recurrence rules (RFC 5545) into concrete instances
- Build busy timeline per user (merge overlapping intervals)
- Invert to free time per user
- Intersect both users' free periods
- Clip to waking hours (7am-11pm local for each partner)
- Filter: minimum 30 minutes
- Score: log-duration + evening bonus + weekend bonus - time decay
- Write top 20 to `overlaps/{coupleId}/windows/latest`

### 2. onOverlapWrite

- **Trigger**: Firestore onWrite on `overlaps/{coupleId}/windows/latest`
- Skip if no windows or content unchanged
- Fetch FCM tokens for both partners
- Send push: "New free time found! [date] at [time] for [duration]"
- Prune stale FCM tokens

### 3. onInviteCreate

- **Trigger**: Firestore onCreate on `invites/{code}`
- Generate deep link for the invite code
- Write link URL back to invite doc
- Set TTL for cleanup

### 4. cleanupExpiredInvites (scheduled)

- **Trigger**: Pub/Sub schedule, daily
- Query invites where expiresAt < now and status = pending
- Batch update status to expired

## Google Calendar Integration

- OAuth2 via `google_sign_in` with calendar.readonly scope
- Freebusy API only — no event titles (privacy-first)
- Primary calendar, 14-day lookahead
- Synced as TimeBlocks with source=google
- On sync: delete old google blocks → write fresh → triggers onBlockWrite
- Auto-sync on app launch if last sync > 1 hour ago

## Timezone Handling

- All storage in UTC (milliseconds since epoch)
- Each user has IANA timezone string
- Each block stores creation timezone
- Display converts to viewing user's timezone
- Overlap engine uses both timezones for waking-hours clipping
- Cloud Functions: Luxon for timezone math
- Flutter: `timezone` package

## Firestore Security Rules

- **Users**: read/write own doc. Partner can read (coupleId match verified)
- **Couples**: only members can read. Cloud Functions manage status
- **Invites**: any auth user can read/create. Creator or redeemer can update
- **Timeblocks**: only couple members can read/write
- **Overlaps**: only couple members can read. Cloud Functions write only
- **Pairing**: auth users can update coupleId on other users (atomic pairing batch)

## Auth & Session Flow

- Firebase Auth (Google + Apple providers)
- On sign-in: fetch/create user doc, fetch couple if coupleId exists
- Hydrate state before rendering routes
- Router redirects:
  - Not authenticated → auth
  - No timezone → timezone setup
  - No couple → pairing
  - Has couple → home
- On sign-out: clear all state → auth

## Scoring Algorithm

```
base = log2(durationMinutes + 1) * 10
eveningBonus = bothInEvening(17-22) ? +30 : oneInEvening ? +10 : 0
weekendBonus = isSatOrSun ? +15 : 0
timeDecay = -daysFromNow * 0.5
score = round(base + eveningBonus + weekendBonus + timeDecay, 1)
```
